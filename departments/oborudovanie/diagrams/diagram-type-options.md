# Варианты типа схемы

## 1. System architecture — рекомендуется

Покажет компоненты, их границы и интерфейсы: каталог, сборщик, снимки v2,
`core`, дашборд и закупщик. Лучше всего отвечает на вопрос «из чего состоит
модуль и как он встраивается в решение комнаты».

Скрывает подробный порядок ежедневных действий.

## 2. Data flow

Покажет, как данные преобразуются: карточка поставщика → нормализованная
позиция → снимок → сравнение → дайджест. Полезен для проверки контракта и
честных статусов.

Сжимает ответственность людей и границы модулей.

## 3. Process map

Покажет ежедневный цикл закупщика и ручную точку решения: получить список,
снять снимок, сравнить, прочитать сигнал, принять действие.

Скрывает технические интерфейсы и состав файлов.
