# PRD · Отдел «Оборудование кухни»

## Контекст

Комната 4 хакатона AI Mindset S26 строит мониторинг поставщиков для ресторана.
Каждый отдел отвечает за собственную категорию и подключается к общему
дашборду через снимки цен в контракте v2.

Этот отдел ведёт кухонное оборудование: мясорубки, слайсеры, печи,
холодильники и связанные с ними системы хранения. Владелец отдела — Кирилл.

## Проблема

Закупщик вручную проверяет карточки поставщиков и не всегда вовремя замечает,
что нужное оборудование подорожало, стало недоступно или сменило статус цены.
Это затягивает поиск альтернативы и создаёт риск закупки на худших условиях.

## Цель

Ежедневно давать закупщику один честный дайджест по выбранным позициям
оборудования: изменение цены и процента, наличие и полнота данных по
поставщикам. Инструмент информирует; выбор поставщика и заказ остаются за
человеком.

## Пользовательский сценарий

1. Айгуль передаёт отделу список позиций и карточек поставщиков.
2. Отдел сохраняет по каждой карточке текущую цену, валюту, наличие и статус
   источника в снимок.
3. Общий `core` сравнивает два последних снимка каждого источника.
4. Закупщик открывает дашборд и видит, что подорожало, подешевело, появилось,
   исчезло или не удалось проверить.
5. Закупщик принимает решение о закупке самостоятельно.

## Границы ответственности

Отдел отвечает за:

- каталог позиций своего домена и ссылки на карточки поставщиков;
- извлечение текущей цены и наличия;
- снимки в `data/*.json`;
- при необходимости — собственную страницу `index.html`.

Отдел не отвечает за автоматическое оформление заказа, выбор поставщика вместо
закупщика и изменение общего ядра без согласования с комнатой.

## Входные данные

Список от Айгуль содержит для каждой позиции название, артикул/модель,
категорию и ссылки поставщиков. Список является конфигурацией: его можно
добавить без изменения логики сбора снимков.

## Контракт результата

Каждый источник записывается отдельным снимком в `data/`:

```json
{
  "taken_at": "2026-08-29T12:00:00+03:00",
  "source": "supplier.example",
  "source_status": "ok",
  "items": {
    "ARTICLE-123": {
      "shop": "supplier.example",
      "title": "Название модели",
      "price": 32100,
      "currency": "RUB",
      "price_status": "listed",
      "in_stock": true
    }
  }
}
```

Правила честности:

- недоступный источник — `source_status: "unreachable"`, а не «товар пропал»;
- цена «по запросу» или заглушка — `price_status: "on_request"`;
- проценты считаются только для сравнимых цен в одной валюте;
- рост от 5% — предупреждение, от 10% — критичный сигнал.

## Критерий «решило»

За один просмотр закупщик понимает: какие позиции изменились, насколько,
изменилось ли наличие и по каким поставщикам данных нет. Два снимка минимум
по одному доступному источнику собираются командой
`python -m core.build --data departments/oborudovanie/data` без доработки
общего `core`.

## Следующий шаг

Получить список позиций от Айгуль, выбрать из него 3–8 позиций и 1–3 источника,
снять первый честный снимок.
